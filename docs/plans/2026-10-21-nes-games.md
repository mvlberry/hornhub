# NES Games Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Add a Hugo games page with a browser NES emulator and two owner-configurable ROM slots, without bundling games.

**Architecture:** A dedicated `/games/` page uses a Hugo data file for the game catalog and a same-origin, version-pinned JSNES distribution. A page-scoped controller manages loading, playback, audio and input; a local file picker reads ROMs in-browser without uploading. Existing editorial styling, private ICP settings and uncommitted user content remain intact.

**Tech Stack:** Hugo 0.168.0, JSNES, vanilla JavaScript, CSS, Node built-in tests, Chromium DevTools Protocol.

---

### Task 1: Pin the emulator dependency

- Retrieve JSNES package metadata from the official npm registry; pin its exact version and verify the package integrity before vendoring the browser distribution and license.
- Inspect the package's Browser implementation; use the stable NES core API with custom frame/audio/input integration, without depending on Browser-private fields.
- Do not download or include third-party ROMs.

### Task 2: Build the page and configurable catalog

**Files:** `content/games.md`, `layouts/_default/games.html`, `data/games.yaml`, `assets/css/nes-player.css`, `static/roms/README.md`.

- Add two empty, honest game slots and a local file picker.
- Use a 256×240 pixel canvas, restrained console styling, visible status, keyboard instructions and touch controls.
- Load emulator assets only on this page; preserve the user's existing navigation changes.
- Verify with `hugo --gc --minify --cleanDestinationDir` and inspect `/games/` output.

### Task 3: Implement and test lifecycle and input

**Files:** `assets/js/nes-player.js`, `tests/nes-player.test.cjs`.

- Add tests for invalid headers, oversized/truncated files, URL restrictions and valid synthetic NROM data before implementation.
- Support loading a configured same-origin ROM or a local `.nes` file, pause/resume, restart, audio toggle, fullscreen and touch/keyboard input.
- Abort superseded requests, prevent sticky keys, pause on hidden pages, and show recoverable errors without losing working controls.
- Run `node --test tests/nes-player.test.cjs`; use an original generated test ROM, never a commercial ROM.

### Task 4: Verify and document

**Files:** `README.md`, source files above.

- Document the exact ROM directory, catalog fields, supported format and public-hosting implications.
- Test real browser frame rendering, local file input, controls, error/recovery, audio, desktop/mobile layout and no-ROM state.
- Confirm no ROMs, private configuration or unrelated user edits are included in any commit.
- Keep publication separate if it would require committing the user's unrelated navigation/content edits.

## Local verification

- Ten Node tests pass, covering format/size/URL validation, bounded response reading, real core execution, a generated audible pulse and the worklet's bounded stereo queue.
- Hugo production build passes with no emulator assets on the homepage.
- Isolated Chromium checks use only an original synthetic ROM created in memory: frame pixels, keyboard down/up, pause/resume, restart, AudioWorklet running/muted, fullscreen, invalid/missing ROM recovery, superseded loads and back-forward-cache handling.
- Desktop and mobile layouts were visually reviewed. Small-screen system buttons use a separate row to avoid wrapped labels.
- No ROMs have been added. Existing user edits to navigation, homepage, about page and new article remain untouched. Publication is not part of this local implementation handoff.
